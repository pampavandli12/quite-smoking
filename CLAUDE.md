# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`AGENTS.md` holds the repository guidelines (style, commit format, PR requirements) and applies here too. This file adds commands and architecture context.

## Commands

```bash
npm ci                                   # install from lockfile
PAYWALL_BYPASS=true npm start            # Metro with subscription screen skipped (restart Metro after changing)
PAYWALL_BYPASS=true npx expo run:android # build + install the Android dev client
npm test                                 # Jest (jest-expo preset, --runInBand)
npx jest utils/__tests__/statistics.test.ts   # single test file
npx jest -t 'name of test'               # single test by name
npm run typecheck                        # tsc --noEmit, strict
npm run lint                             # expo lint
npm run build:check                      # export Android JS bundle to .test-build/
```

CI (`.github/workflows/quality.yml`, Node 20.19.4) runs test → typecheck → lint → build:check on every PR and push to `main`. Before opening a PR, run all four.

The app needs a development build (not Expo Go) because of native modules like `react-native-purchases`. `android/` is generated by Expo CNG from `app.config.js` and is not committed. Put native changes in config plugins under `plugins/` (such as the R8/ProGuard hardening), not in hand edits to `android/`.

## Architecture

**Layering:** `app/` screens → `services/` (domain logic, write orchestration) → `db/` (SQL). Screens must not touch the database directly. Tests live next to the code in `__tests__/` folders (`db/`, `services/`, `utils/`, `components/`).

**Startup (`app/_layout.tsx`):** the splash screen stays up until fonts load, `initializeDatabase()` finishes, and `PurchaseService.initialize()` resolves. If the database fails, a retry screen is shown. If purchases fail, the app continues anyway. `app/index.tsx` is the paywall/entry route. It reads `PAYWALL_BYPASS` from `Constants.expoConfig.extra` (env var → `app.config.js` → `extra`), then routes into `setup-smoking` or `(tabs)`.

**Database (`db/`):** expo-sqlite (`quitSmoking.db`) with a Drizzle schema in `db/schema.ts`, but most queries are raw SQL. Key points:
- Every access goes through the wrappers in `db/client.ts` (`dbRunAsync`, `dbGetAllAsync`, `dbTransactionAsync`, …). They serialize all operations through one promise queue. Don't call `expoDb` directly, and use `dbTransactionAsync` for multi-step writes.
- Migrations are in `db/migrations.ts`, versioned by `PRAGMA user_version` (`DATABASE_VERSION`). Each migration runs in its own transaction. To add one, append to `DATABASE_MIGRATIONS` and bump `DATABASE_VERSION`. `ensureProductSchema()` then additively reconciles columns and tables, so a hot reload or partial migration can't break the schema. Migrations must be idempotent.
- Timestamps may be legacy strings or epoch numbers (`timestamp: number | string`). Keep both readable.
- Pre-existing users get an `app_metadata.legacy_access = 'true'` flag that grants the `legacy` access tier.

**Access and purchases:** `services/purchases.ts` is a RevenueCat singleton (entitlement `QuitSmoke Pro`). Android release builds require a `goog_` key. A missing, placeholder, or test key in production disables purchases and never enables mock purchases. `services/accessService.ts#resolveFeatureAccess` maps state to a tier (`premium` / `legacy` / `free`) and then to feature flags (`canUseUnlimitedRescue`, `canViewAdvancedInsights`, `canExportReports`, …). Gate features through these flags, not through ad-hoc entitlement checks. The RevenueCat key comes from `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY` (`.env.local` locally, `eas.json` per build profile). `app.config.js` falls back to a dev test key.

**Cross-screen refresh:** after a mutation, services call `emitDataChange(domain)` from `services/dataEvents.ts`, where domain is `history | craving | plan | preferences | report`. Listeners use `subscribeToDataChanges`, though no screen subscribes to it yet. New write paths should still emit the matching domain.

**UI:** react-native-paper MD3. `theme/index.ts` exports `lightTheme`/`darkTheme` (typed `AppTheme`, which adds `appColors`) plus `designTokens` (spacing, radius, motion). Use `useTheme<AppTheme>()`. Shared primitives are in `components/ui.tsx`. Icons go through `components/AppSymbol.tsx`. Motion respects the user's reduced-motion preference (`hooks/useAppMotion.ts`, `utils/motion.ts`).

## Change discipline

- Database and RevenueCat changes also require the manual checklists in `docs/verification/` (`database-migration.md`, `purchase-smoke-test.md`, `release-checklist.md`).
- `docs/refactoring/` tracks the phased refactor under a "global behavior lock". Preserve route names, the SQLite filename, schema, and stored values, RevenueCat keys, entitlement, and offering, env vars, build profiles, UI copy, and calculations. Keep refactors separate from feature changes.
